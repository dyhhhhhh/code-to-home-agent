# AI 直播从 0 到 1 调研文档

**主题：如果我要从零开始做一个 AI 直播间，需要什么、怎么买、多少钱、怎么落地**  
**版本：2026-06-01**  
**说明：本文中的价格为公开资料和常见市场报价区间整理，不构成采购承诺。实际价格会随平台政策、套餐活动、并发、画质、直播时长和定制深度变化。**

## 1. 我到底想做什么

我想做的不是一个“会念稿子的数字人视频”，而是一个可以持续直播、能讲商品、能回答弹幕、能被人工接管、能控制风险的 AI 直播系统。

最小目标可以先定成：

```text
商品资料准备好
AI 生成讲解话术
TTS 把文字变成语音
画面展示商品图和字幕
OBS 推流到直播平台
人工随时能暂停或接管
```

升级目标再变成：

```text
数字人出镜
读取弹幕
AI 根据商品知识库回答
敏感内容先审核
高风险问题转人工
直播结束后自动复盘
```

最终形态不是“无人瞎播”，而是：

```text
AI 负责重复讲解和基础互动
真人负责高风险判断、活动策略和关键成交
系统负责审核、推流、日志、数据复盘
```

## 2. 一条 AI 直播链路需要哪些东西

我从零开始拆，至少需要 8 个模块。

| 模块 | 作用 | 可先简化吗 |
|---|---|---|
| 商品资料 | 告诉 AI 能说什么 | 不能省 |
| 大模型 | 生成话术、理解弹幕 | 可以先用在线 API |
| 审核规则 | 防止乱报价格、违规承诺 | 不能省 |
| TTS | 把文字变成语音 | 可以用现成服务 |
| 画面层 | 商品图、字幕、数字人 | 第一版可不用数字人 |
| 推流工具 | 推到抖音/视频号/快手/B站/淘宝等 | OBS 最简单 |
| 弹幕采集 | 读取观众问题 | 第一版可先手动 |
| 人工接管 | 出错时立刻停播/改口径 | 不能省 |

所以它的核心链路是：

```text
资料 -> AI 生成 -> 审核 -> 语音 -> 画面 -> 推流 -> 弹幕 -> 再生成
```

## 3. 最低成本版本怎么做

如果只是想验证这个方向，不建议一上来买昂贵数字人平台。

我会先做一个“无数字人 MVP”：

```text
商品图 / 背景图
+ AI 生成话术
+ TTS 语音
+ 字幕
+ OBS 推流
+ 人工监控
```

它看起来不如数字人高级，但足够验证几个关键问题：

- AI 是否会乱说。
- 话术是否能讲清楚商品。
- 直播间是否有人停留。
- 平台是否允许这种形式。
- TTS 声音是否能接受。
- 推流是否稳定。
- 人工能否及时接管。

### 3.1 MVP 采购清单

| 项目 | 选择 | 估算费用 |
|---|---|---:|
| 电脑 | 现有电脑即可，推荐 16GB 内存以上 | 0-4000 元 |
| OBS | 免费 | 0 元 |
| 商品图/背景图 | 自己做或用设计工具 | 0-500 元 |
| 大模型 API | 在线 API 或中转 API | 100-1000 元/月 |
| TTS | 云服务或本地 TTS | 50-1000 元/月 |
| 字幕生成 | 自研或 OBS 插件 | 0-500 元 |
| 审核词库 | 自己整理 | 0 元 |
| 推流成本 | 多数平台自身不额外收基础推流费，云转推另算 | 0-数百元/月 |

**MVP 总体预算：**

```text
极简验证：100-500 元/月
比较舒服：500-2000 元/月
带简单外包设计：2000-5000 元/月
```

这一版不追求“像真人”，只追求系统闭环跑通。

## 4. 数字人版本怎么做

如果 MVP 有效果，再升级数字人。

数字人方案大概分三类。

### 4.1 SaaS 数字人直播平台

适合不想自研、希望快速开播的人。

通常提供：

- 数字人形象。
- 声音。
- 话术配置。
- 商品配置。
- 推流。
- 部分弹幕互动。
- 简单后台。

优点：

- 上手快。
- 不需要自己处理口型同步。
- 画面效果比纯商品图好。

缺点：

- 可控性有限。
- 深度接入商品系统较难。
- 弹幕互动和风控能力要看平台。
- 长期费用不一定低。

### 4.2 云厂商数字人直播

适合有技术人员，想和自己的系统打通。

典型能力：

- 控制台创建数字人直播间。
- 文本生成数字人视频。
- 数字人推流。
- API 启停直播间。
- 接入云直播、转推、RTC 等基础设施。

优点：

- 稳定性相对强。
- API 和云服务体系完整。
- 更适合企业集成。

缺点：

- 配置和计费复杂。
- 互动、商品、审核仍需自己做一部分。
- 成本和使用时长强相关。

### 4.3 自研数字人管线

适合技术团队长期做产品。

需要自己处理：

- 数字人驱动。
- TTS。
- 口型同步。
- 画面渲染。
- 推流。
- 弹幕。
- 审核。
- 后台。

优点：

- 可控性最高。
- 可以做差异化。
- 后期边际成本可能更低。

缺点：

- 开发周期长。
- 效果难打磨。
- 初期不适合快速验证商业方向。

## 5. 公开报价参考

下面是我整理的部分公开报价，用来建立成本感知。

### 5.1 腾讯云 AIGC 直播 / 数字人直播

腾讯云文档显示，AIGC 直播/数字人直播是云直播的付费增值能力。

公开计费要点：

| 项目 | 公开价格 |
|---|---:|
| 增值功能基础费 | 0.1 元/计费单位 |
| 预设形象生成数字人 | 等效 6 元/分钟 |
| AIGC 形象生成 | 等效 1 元/次 |
| AIGC 数字人 | 等效 42 元/分钟 |
| 拉流转推任务时长 | 0.002 元/分钟 |

这里要注意，真正花费取决于你生成数字人视频的分钟数、是否使用 AIGC 形象、是否转推第三方平台。

粗略理解：

```text
预设数字人生成 1 小时内容：约 360 元
AIGC 数字人生成 1 小时内容：约 2520 元
拉流转推 1 小时：约 0.12 元
```

这说明数字人“生成分钟数”才是大头，单纯转推不是大头。

来源：腾讯云《AIGC直播/数字人直播》计费文档。

### 5.4 市场常见 SaaS 价格区间

除了云厂商，市面上还有大量第三方数字人直播 SaaS。不同服务商差异很大，常见价格通常和这些因素有关：

- 是否提供数字人形象。
- 是否支持真人形象克隆。
- 是否支持声音克隆。
- 是否支持弹幕互动。
- 是否支持多平台推流。
- 是否支持商品库。
- 是否支持人工接管。
- 是否按月、按年、按直播时长计费。

常见区间可以按采购感知粗分：

| 类型 | 常见区间 |
|---|---:|
| 低价工具型 | 99-999 元/月 |
| 中小商家 SaaS | 1000-5000 元/月 |
| 品牌直播方案 | 5000-30000 元/月 |
| 定制数字人 + 系统集成 | 数万元起 |

这类价格变化很大，必须以合同、试用效果和实际功能为准。

## 6. 三套落地预算

### 6.1 方案 A：个人/小团队验证版

目标：花最少的钱验证“AI 直播能不能跑起来”。

配置：

- OBS。
- 商品图。
- 在线大模型 API。
- TTS。
- 手动维护商品资料。
- 人工看直播间。

预算：

```text
一次性：0-3000 元
每月：100-1000 元
```

适合：

- 还没有确定品类。
- 只是验证 AI 话术和直播形式。
- 不想被数字人平台年费绑住。

不适合：

- 需要高拟真数字人。
- 需要长期无人直播。
- 需要直接商业投放。

### 6.2 方案 B：中小商家数字人版

目标：真正搭一个可播的数字人直播间。

配置：

- 数字人 SaaS 或云厂商服务。
- 商品知识库。
- TTS 和数字人驱动。
- OBS 或平台推流。
- 基础弹幕问答。
- 敏感词和固定话术。
- 人工接管。

预算：

```text
一次性：3000-20000 元
每月：1000-10000 元
```

适合：

- 标品电商。
- 本地生活。
- 闲时直播补位。
- 已经有商品和基础运营能力。

### 6.3 方案 C：企业级集成版

目标：把 AI 直播接进企业自己的商品、客服、订单、审核和数据系统。

配置：

- 定制数字人。
- 定制声音。
- 商品系统对接。
- 价格库存同步。
- 客服系统对接。
- 内容审核。
- 多平台推流。
- 直播数据分析。
- 权限和人工接管后台。

预算：

```text
一次性：5 万-50 万元+
每月：1 万-10 万元+
```

适合：

- 多品牌、多账号、多平台。
- 有稳定货盘和投放预算。
- 需要长期规模化直播。
- 需要和内部业务系统打通。

## 7. 从 0 开始的实施步骤

### 7.1 第 1 周：先不买数字人

要做的事：

- 选一个商品或一个品类。
- 整理商品资料表。
- 整理 50-100 条 FAQ。
- 写直播开场、讲品、转场、结尾话术。
- 搭 OBS。
- 接一个 TTS。
- 手动推流测试。

验证：

- 话术能不能听。
- 声音能不能接受。
- 画面有没有基本专业感。
- 平台规则是否允许。

### 7.2 第 2-3 周：接入大模型

要做的事：

- 用大模型生成讲品话术。
- 给大模型喂商品资料。
- 建立禁止词和固定口径。
- 对生成内容做审核。
- 把通过审核的内容交给 TTS。

验证：

- 是否乱报价格。
- 是否编造功能。
- 是否能回答 FAQ。
- 是否能在拒答时说得自然。

### 7.3 第 4 周：试数字人平台

要做的事：

- 试用 2-3 个数字人平台。
- 比较形象、声音、口型、延迟、推流稳定性。
- 测试 1 小时直播。
- 记录平台规则和成本。

验证：

- 观众是否明显更愿意停留。
- 数字人是否影响信任感。
- 长时间播报是否稳定。
- 成本是否能被成交覆盖。

### 7.4 第 2 个月：接弹幕和人工接管

要做的事：

- 弹幕采集。
- 问题分类。
- 商品知识库检索。
- AI 回答。
- 审核。
- 人工接管按钮。
- 直播日志。

验证：

- 回答延迟是否可接受。
- 是否能过滤无关弹幕。
- 高风险问题是否会转人工。
- 人工接管是否足够快。

## 8. 我会怎么选型

如果只是试水，我不会一开始买 3 万/年的服务。

我会按这个顺序：

```text
先做无数字人 MVP
-> 再试低价 SaaS 数字人
-> 再试云厂商数字人
-> 数据证明有效后再定制
```

原因很简单：

- AI 直播不一定适合所有品类。
- 数字人效果好，不等于转化好。
- 平台规则可能限制无人直播。
- 话术和商品资料比数字人形象更重要。
- 先买年费容易被工具绑住。

我最看重的不是“数字人像不像”，而是：

```text
能不能稳定播
会不会乱说
能不能接管
能不能回答商品问题
成本能不能被成交覆盖
```

## 9. 哪些钱值得花，哪些钱先别花

### 9.1 值得先花

- 商品资料结构化。
- FAQ 整理。
- 好一点的 TTS。
- 基础画面设计。
- 审核词库和固定话术。
- 人工接管流程。

这些会直接影响直播质量和风险。

### 9.2 可以后花

- 高拟真数字人。
- 声音克隆。
- 多平台矩阵。
- 复杂弹幕自动化。
- 私有化部署。
- 高级数据看板。

这些适合在方向验证后再投入。

### 9.3 不建议一开始花

- 未验证品类就买年费套餐。
- 一上来定制昂贵数字人。
- 完全无人直播系统。
- 没有审核层的自动弹幕回答。
- 没有人工接管的商业直播。

## 10. 合规和风险清单

AI 直播最容易出问题的不是技术，而是说错话。

### 10.1 必须避免

- 乱报价格。
- 乱说库存。
- 夸大效果。
- 承诺不存在的售后。
- 医疗、金融、教育结果类承诺。
- 诱导站外交易。
- 使用未授权真人形象。
- 使用未授权声音克隆。
- 平台不允许的无人直播形式。

### 10.2 必须具备

- 固定价格来源。
- 固定售后口径。
- 敏感词拦截。
- 高风险问题拒答。
- 人工接管。
- 直播日志。
- 一键停播。

### 10.3 平台规则要单独确认

上线前要确认：

- 平台是否允许数字人直播。
- 是否需要标识虚拟主播或 AI 生成内容。
- 是否允许无人值守。
- 是否允许循环播报。
- 是否允许自动读取弹幕并回答。
- 是否对电商话术有特殊要求。

不同平台规则变化很快，这块不能靠经验猜。

## 11. 最终建议

如果从 0 开始，我建议路线是：

```text
第 1 步：无数字人 MVP，验证话术和推流
第 2 步：接 TTS 和审核，保证不乱说
第 3 步：试用数字人 SaaS，看停留和转化
第 4 步：接弹幕问答，但保留人工接管
第 5 步：有数据后再考虑年费、定制和企业集成
```

不要把 AI 直播理解成“买一个数字人软件就能赚钱”。更准确地说，它是一套直播生产系统：

```text
资料
+ 模型
+ 审核
+ 声音
+ 画面
+ 推流
+ 互动
+ 人工接管
+ 数据复盘
```

真正影响成败的是货盘、话术、合规、运营和成本控制。数字人只是其中一个展示层。
