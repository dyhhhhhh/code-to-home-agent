# Code Agent to Home Agent

把 code agent 的工作范式迁移到家庭环境，构建一个以本地大模型为中心、以安全硬件代理为边界的 home agent 设想。

这个仓库不是一个已经可以直接接管家庭设备的产品，也不是另一个单纯的智能家居聊天控制插件，而是一份面向开源社区的技术路线草案。它关注更上层的问题：如何把 code agent 的观察、行动、验证循环迁移到家庭环境，并让真实家电在安全代理层、权限系统和状态验证闭环中被编排。

它试图回答一个问题：

> 如果 code agent 已经能阅读代码、调用工具、修改状态、验证结果，那么能不能把同样的 agent 思路改写成一个家庭智能体？

我们的判断是：可以，但真正的难点已经不主要是大模型，而是家庭硬件、协议、传感器、安全权限和可靠执行闭环。

## 核心观点

当前开源大模型已经足以承担 home agent 的大量认知任务：

- 理解自然语言家庭指令。
- 把模糊意图拆解成多设备动作。
- 生成自动化规则。
- 解释为什么执行或拒绝某个动作。
- 总结家庭传感器和设备日志。
- 在工具约束下调用 Home Assistant、Matter Hub 或厂商 API。

但 home agent 不能只是一个会聊天的大模型。成熟的家庭智能体需要完整系统：

```text
用户意图
  ↓
语音识别 / 文本输入
  ↓
本地大模型
  ↓
任务规划
  ↓
权限检查
  ↓
风险分级
  ↓
设备中枢
  ↓
家电代理模块
  ↓
状态回读与传感器验证
  ↓
日志记录与人工接管
```

一句话概括：

> 大模型可以成为 home agent 的脑，但不能单独成为 home agent 的刹车、神经系统和法律。

## 从 Code Agent 到 Home Agent

code agent 的基本循环通常是：

```text
读取代码仓库
→ 理解任务
→ 制定计划
→ 调用工具
→ 修改文件
→ 运行测试
→ 根据反馈修正
→ 提交结果
```

home agent 可以映射成：

```text
读取家庭状态
→ 理解家庭意图
→ 制定家庭动作计划
→ 调用设备工具
→ 修改家庭环境
→ 读取设备回执和传感器
→ 根据反馈修正
→ 记录日志并向用户解释
```

两者的相似性在于：agent 都不是直接“魔法般完成任务”，而是在一个工具化环境里观察、行动、验证、迭代。

两者的关键差异在于：家庭是现实世界，错误成本更高。

| 维度 | Code Agent | Home Agent |
|---|---|---|
| 环境 | 文件、命令行、测试、Git | 家电、传感器、房间、人、门锁、能源 |
| 动作 | 编辑文件、运行命令、调用 API | 开灯、调温、关窗、启动设备、提醒用户 |
| 验证 | 编译、测试、lint、diff | 设备回执、传感器状态、功耗、图像、人工确认 |
| 回滚 | Git revert、恢复文件 | 手动接管、停止设备、恢复场景、报警 |
| 风险 | 代码错误、数据损坏 | 安全、隐私、火灾、水浸、门锁、儿童老人 |
| 权限 | 文件系统和命令权限 | 家庭成员、房间、设备风险、时间、场景 |

## 为什么不是“大模型直接控制一切”

错误架构：

```text
LLM → 继电器 → 家电
```

正确方向：

```text
LLM → 行动请求
    → 权限系统
    → 风险分级
    → 本地规则引擎
    → 安全硬件代理
    → 家电原控制系统
    → 状态验证
    → 审计日志
```

AI 可以请求动作，但最终是否执行，应由本地安全层决定。尤其是门锁、燃气、配电、厨房加热设备、医疗设备、报警系统，必须有硬规则和人工确认。

## 五级家电接入模型

为了让传统家电进入 home agent 系统，可以按风险和侵入程度分级：

| 等级 | 名称 | 做法 | 适用设备 |
|---|---|---|---|
| Level 0 | 只观察 | 只加传感器，不加控制 | 燃气灶、冰箱、配电箱、医疗设备 |
| Level 1 | 非侵入控制 | 红外、蓝牙、机械按键器、遥控协议 | 空调、电视、风扇、音响 |
| Level 2 | 电源级控制 | 智能插座、继电器、接触器 | 台灯、普通风扇、低风险小电器 |
| Level 3 | 低压接口接入 | UART、RS485、CAN、GPIO、干接点 | HVAC、新风、地暖、电动窗帘 |
| Level 4 | 替换控制板 | 自定义控制板接管原硬件 | 实验设备、低风险 DIY 改造 |
| Level 5 | 原生 AI 家电 | 出厂提供标准能力描述和安全策略 | 未来家电 |

现实路径应从 Level 0 到 Level 3 起步。Level 4 只适合专业人员和低风险设备。Level 5 是行业最终形态。

## Home Agent 的最小可行架构

一个今天就可以开始实验的版本：

```text
Home Assistant
+ Matter / Zigbee / Thread 网关
+ 本地开源 LLM
+ 本地语音识别
+ 本地 TTS
+ 传感器网络
+ 权限和规则引擎
+ 手机或中控屏确认
```

推荐先接入低风险设备：

- 灯光。
- 窗帘。
- 空调。
- 新风。
- 空气净化器。
- 电视和音响。
- 扫地机器人。
- 温湿度、人体存在、门窗、光照、CO2、水浸、烟雾、燃气传感器。

高风险设备先做监测，再谨慎控制：

- 门锁。
- 燃气。
- 配电箱。
- 热水器。
- 厨房加热设备。
- 医疗和照护设备。

## 开源模型的位置

开源模型适合负责：

- 意图理解。
- 多步规划。
- 工具调用参数生成。
- 规则草案生成。
- 家庭状态解释。
- 操作日志总结。
- 家庭偏好记忆检索。

不适合单独负责：

- 开门。
- 打开燃气。
- 停用报警系统。
- 远程分享摄像头。
- 医疗判断。
- 儿童或老人安全关键决策。
- 大功率设备无人启动。

这些动作必须经过权限、硬规则和人工确认。

## 发布目标

这个仓库希望成为一个开放讨论起点：

- 如何把 code agent 的观察-行动-验证循环迁移到家庭。
- 如何定义家电能力描述协议。
- 如何设计家庭权限和风险等级。
- 如何让开源大模型在本地安全运行。
- 如何让传统家电通过安全代理模块接入 home agent。

## 安全声明

本仓库内容是架构和研究设想，不是电气施工指南。任何涉及市电、燃气、门锁、配电箱、厨房加热设备、医疗设备的改造，都应由具备资质的专业人员执行，并遵守当地法律法规和安规要求。

home agent 的原则不是让 AI 强行接管家庭，而是让家庭设备在可授权、可验证、可解释、可接管的前提下协同工作。
